# 视觉 Agent 图片复核（0.8.0）

## 直接使用

安装当前开发版并重启 Harness，选择已配置且支持图像输入的模型。数据目录与 allowedRoots 沿用已有设置。在项目中直接提出：

> 对这个项目进行图片重复复核。准备正文和 SI 的图片，必要时拆分面板。不要只看像素算法命中的候选；启动独立视觉任务，逐对查看原图和高清裁剪，区分共同坐标轴、合理复用和实验内容重复。对疑点标出两端区域，查看生成的对照图；不确定就记录不确定。最后重新核对并导出报告，同时列出未检查范围。

插件通过原生工具把图片交给**当前 Harness Agent 的视觉模型**，利用其正常的“看图→调用工具→继续判断”循环。它不偷偷启动另一模型、不自行选择第三方服务、不另存 API 密钥。单独运行 `paper_audit_run` 仍只做程序检查并汇入已保存的模型观察，不会自动发出视觉推理请求。图片会经你已配置的模型路由处理。

如果当前模型不声明支持图片，或者 Harness 附件服务不可用，任务会明确失败并可重试；不会用 OCR 冒充看图，也不会把失败记作正常负例。需要切换到已配置的视觉模型后再试；不能对同一个不支持图片的路由反复重试。

## 多模态模型与 OCR 的分工

图片审核由当前多模态模型负责：先看完整原图，再看局部放大，比较科学内容并解释疑点。插件负责提供图片、组织任务、校验来源和保存观察。OCR 只辅助抄取文字、数字和表格，不参与判断图像是否重复或结论是否成立，也不是进入视觉队列的条件。

0.10.0 起，新项目的整篇工作流默认不做 OCR。旧项目保留原设置。工作流返回 `reviewHandoff` 供 Agent 继续看图；即使手动启用的 OCR 失败，原图仍可查看。材料准备完成与图片审核完成分别记录。图片审核也可在 **设置 → 论文核对** 中调整预算。

## 原生工具流程

1. 用已有 `paper_audit_workflow` 或 `prepare_image_audit` 准备图片，检查未渲染材料。复杂整页可用 `paper_audit_extract_panels` 拆分；面板来自候选切分时不能默认认定边界正确。
2. `paper_audit_visual_review(action="start")` 建立独立任务。默认选取最多 200 张已准备图片，比较所有两两组合及同图内部重复，首批最多 2000 个任务。小项目直接逐对检查；大型项目可显式选择图片、类型范围、比较对或批次。**不以像素查重命中作为入队条件。**
3. `paper_audit_visual_pair` 提供下一任务的 A/B 原图。成功时返回两个原生图片附件及回执；每端附原件哈希、图像哈希、尺寸、原文位置和可定位的上下文。Agent 必须实际查看两张附件。
4. 细节不清时再次调用该工具，提供 `cropsJson=[A矩形,B矩形]`，某端不裁剪则填 null。必须先获取完整原图；裁剪尺寸最少 16×16。原件不修改。
5. `paper_audit_submit_visual` 保存模型观察。正例和可能合理复用都必须提交两端区域、对应特征、变换和解释；坐标按注册原图的像素填写。共享坐标轴/模板本身不能作为“科学内容重复”的依据。
6. 对每组区域调用 `paper_audit_visual_comparison` 查看实际生成的红框对照图。坐标错了或结论需修改时，使用 `visual_review(action="reopen",taskId,reason)`；重新取图再提交。原观察保留在 history，旧回执不能用于新一轮提交。
7. 持续处理 nextTaskId。失败可 retry_failed；extend 添加下一批；cancel 取消。进程重启后可读取同一个 jobId 继续。源文件、图像清单或图片类型变化使旧任务失效，需建立新任务。
8. 重新调用 `paper_audit_run`，再导出 MD/JSON/CSV。视觉疑点会进入问题列表及共同原因分组；未发现对应的观察保存在报告中，但不计作科学验证通过。

## 范围与设置

start 的 optionsJson 示例：

```json
{"mode":"all","includeSelf":true,"maxAssets":200,"maxPairs":2000}
```

- `assetIds`：指定图片；未选材料列为范围外。
- `pairs`：显式 `[[assetIdA,assetIdB],...]`；反向重复不允许，范围外组合数量保留。适合指定复核或冻结验证集。
- `mode="same_type"`：只比较同类或涉及 unknown 的图片，跨类排除数量明确显示。分类不能当作已确认结构/实验身份。
- `includeSelf`：是否检查同图两个区域。正例区域不能大幅重叠，避免拿一个区域与自己比较。
- `maxAssets`：1–500；`maxPairs`：每批 1–10000。分页、失败和范围外材料不会被静默当作已检查。

原图与直接裁剪子图之间默认排除。每个任务最多保存 16 次图片视图；需更多细节时可另拆面板或建立定向任务。任务数量会随图片数量平方增长，应结合预算安排。

## 结果及证据

模型返回四类观察：

| decision | 含义 |
|---|---|
| suspected_duplicate | 具体实验内容疑似重复，需复核 |
| possible_legitimate_reuse | 观察到对应内容，可能是共同对照/正文与 SI 复用，需核对用途 |
| no_correspondence | 本次观察未找到对应；不证明没有重复 |
| uncertain | 图像、细节或上下文不足，保留弃判 |

结果示例：

```json
{
  "decision":"suspected_duplicate",
  "basis":"scientific_content",
  "reason":"此处填写实际观察依据，不能套用示例作为论文判断。",
  "checkedFeatures":["比较两端实验区域的特征排列"],
  "limitations":["需要原始未压缩图进一步确认"],
  "typeCandidates":["microscopy","microscopy"],
  "regions":[{
    "a":{"x":20,"y":30,"width":120,"height":100},
    "b":{"x":80,"y":45,"width":120,"height":100},
    "feature":"填写具体对应特征",
    "transform":"translation"
  }]
}
```

以上是格式示例，不是真实观察。`typeCandidates` 是模型候选，不会覆盖用户确认的图片类型。切换模型后必须向新路由重新提供完整原图。

附件可能被宿主缩小：先用附件尺寸映射回该视图尺寸，裁剪视图再加 crop.x/y，得到原图坐标；面板还保留 parentCrop 以追溯父图。后端检查来源、模型路由、回执、坐标边界及同图区域分离，生成实际对照图。**它不把坐标合法等同于特征确实匹配。** 附件输出准备记录也不能证明模型真正完成了观察。

所有模型结论均保留 needs_review、scientificallyVerified=false。人工决定仍使用已有 review 工具；模型不能替用户确认、认定科研不端或关闭修订问题。

## 评估与已验证边界

当前已验证：独立入队、两端附件/裁剪、失败重试、源变化失效、假回执拒绝、路由切换约束、区域验证、对照图、更正历史、报告和统计。正向视觉判断的自动测试使用明确标注的模拟模型响应；原生 Harness 启动测试验证没有视觉路由时如实失败。**这些测试不是视觉模型检测准确率。**

BioFors 的旧 10 篇/172 对子集仍保留 0.7.0 像素算法结果，不能当作新视觉流程的成绩。可准备不向模型提供参考标签的 10 个论文项目（每个项目保持在 64 个源文件上限内）：

```powershell
python scripts/fetch-biofors.py
node scripts/prepare-visual-benchmark.js "Harness实际dataDir" "BioFors图片目录绝对路径"
```

脚本只创建项目和任务，不调用模型；输出 projectId/jobId 以及所需 allowedRoots，不擅自修改全局配置。在同一个 dataDir 的 Harness 中用视觉模型完成这些任务，重新运行核对，将各项目 JSON 报告导出到一个目录，然后：

```powershell
node scripts/evaluate-visual.js "报告目录绝对路径" "test-output/visual-benchmark/mapping.json的绝对路径"
```

分别输出旧程序基线、视觉观察和组合策略指标。缺失项目、未检查、失败、源失效和 uncertain 都算弃判。组合策略任一正例即提出疑点，双方均为负例才记为负例。该批材料已用于开发，不能再称为新的独立盲测；正式提升成绩还需要未看过的论文和独立参考标注。
