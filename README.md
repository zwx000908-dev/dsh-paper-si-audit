# dsh-paper-si-audit

**Paper–SI Audit** 是一个 DeepSeek Harness 插件，用于核对科研论文正文与补充信息（Supplementary Information，SI）中的数据。它主要面向化学论文，帮助作者查找前后不一致的数值、可疑的表征记录和需要复核的图片，并把问题对应到原文位置。

你可以在 Harness 会话中直接告诉它要检查什么。检查结果会保留原文、计算过程和图片位置，方便你逐项确认，再导出报告。论文原件以只读方式处理。

## 可以用来做什么

| 你想检查的内容 | 插件可以提供的帮助 |
|---|---|
| 正文与 SI 是否一致 | 比较可识别的收率、ee/er 和部分实验条件，保留化合物、方法和条件等上下文，提醒你检查可能对应不上的记录。 |
| 数据格式是否符合要求 | 自定义小数位、有效数字、舍入方式和单位。例如，分别设置 ¹H、¹³C 化学位移、偶合常数 J 和 HRMS 的小数位数。 |
| HRMS 数值是否算对 | 按分子式、同位素、加合物和电荷复算理论 m/z，检查文中 calculated 和 found 的偏差。分子式含义不清时，会列出不同解释。 |
| 核磁记录是否与分子式相容 | 检查报告的氢积分、碳信号及标注碳数，列出数量不符、对应关系不清或信息不足的记录；也可读取谱图中的明确标签，与文字表征对照。 |
| 实验用量和收率是否自洽 | 在条件明确时复算质量、物质的量、浓度和收率；需要假设时，会写明假设及缺少的信息。 |
| 图片是否重复 | 由当前多模态模型查看原图、比较局部区域，记录疑点并生成对照图。插件负责提取图片、安排比较任务和保存证据；程序相似度筛查可提供辅助线索。 |
| 表格与文字结论是否对应 | 读取文字表格，或由多模态模型查看图片表格的表头、单位和单元格；必要时用 OCR 辅助提取文字。核对明确的图表引用，以及能够从表格直接比较的最高值、指定条目等结论。 |
| 化合物材料是否齐全 | 按化合物整理表征文字和图片，并根据你设置的材料清单，指出哪些材料已找到、哪些还没找到或尚未读取。 |
| 修改后是否解决了旧问题 | 保留历史问题和处理意见，重新核对修订稿；将涉及同一通用方法、格式规则或图片的问题集中展示，方便一起查看。 |

图片审核的主要工作由多模态模型完成：查看原图、识别图中内容、比较区域并解释疑点。OCR 只辅助提取文字，不判断图片是否重复或科学内容是否成立。

整篇材料的图像准备、可选 OCR 和分批检查可以中断后继续。报告会说明检查了哪些内容、哪些失败或尚未检查，并支持导出 Markdown、JSON 和 CSV。

## 安装

兼容目标为 **DeepSeek Harness 0.2.2-rc.1**。使用源码或命令行时，需要 **Node.js 24.9.0 或以上**。

目前，`main` 分支为 **0.10.2 开发版**，包含本页介绍的功能。安装命令：

```powershell
dsh plugin --profile paper-audit add "github:zwx000908-dev/dsh-paper-si-audit#main"
```

这条命令将插件安装到名为 `paper-audit` 的独立配置环境（profile）。**如果你使用桌面版 Harness，需要在桌面版对应的 `desktop` profile 中安装并启用插件。** 安装到独立 profile 不会自动启用桌面会话。

安装后，在 Harness 中启用插件组合包（bundle），填写下文的保存目录和论文目录，再按宿主提示重新加载或重启。具体步骤见 [Harness 安装与使用说明](docs/HARNESS.md)。

此前发布的 [v0.2.0 安装包](https://github.com/zwx000908-dev/dsh-paper-si-audit/releases/tag/v0.2.0) 仍可下载，但不包含后续加入的核磁—分子式核对、图片查重和新版设置等功能。需要这些功能时，请使用 `main` 开发版。

## 基础设置

打开 Harness 的 **设置 → 论文核对**，先填写两个目录：

| 设置 | 填什么 |
|---|---|
| `dataDir` | 保存核对项目和报告的目录，例如 `D:/PaperAudit/projects`。 |
| `allowedRoots` | 允许插件读取论文的目录，例如 `D:/Research/manuscript`。目录必须存在；留空时不能导入论文。 |

同一页面中可以设置新项目的默认选项，修改后点击 **保存设置**：

- **核对范围**：检查全部已导入材料，或只检查 SI。
- **检查项目**：选择是否启用 HRMS、核磁、实验复算、图片查重等检查。
- **格式要求**：设置各类数据的小数位数，或导入完整的 JSON/YAML 模板。模板也支持有效数字和单位要求。
- **容差与处理数量**：调整 HRMS 偏差提示阈值、核磁比较容差、每批处理的图片数和比较对数。
- **OCR 与报告**：选择是否启用辅助 OCR（新项目默认关闭），以及报告格式、对照图和证据文字的展示方式。

这里填写的是你的检查偏好。期刊有特定要求时，可以在模板中记录要求及来源；插件不会把自定义数值自动当作期刊规定。[模板示例](profiles/custom-demo.yaml) 仅演示写法。

**全局默认值只影响新建项目。** 已有项目保留自己的设置，也可以只为某一次检查临时调整。例如，直接在会话中说：

> 把这个项目设为只核对 SI，HRMS 容差设为 3 ppm。报告中保留原文证据和图片对照。

或者：

> 这一次把 ¹H 化学位移的小数位要求改为三位，不修改项目默认设置。

每次检查都会保存当时使用的设置。详细字段、重置方法和任务恢复规则见 [设置说明](docs/SETTINGS.md)。模型由 Harness 会话选择，插件没有单独的模型账号或 API Key 设置。

## 使用方法

启用插件后，在 Harness 会话中提供正文和 SI 的文件路径，并说明要检查的内容。例如：

> 请使用 Paper–SI Audit 核对这篇论文的正文和 SI。先告诉我哪些内容能读取、哪些不能读取，再检查数据是否一致、HRMS 是否算对、核磁记录是否与分子式相容。按我提供的模板检查格式。把需要确认的问题、原文位置和计算依据一起列出，最后导出 Markdown 和 JSON 报告。

一次核对通常包括以下步骤：

1. **导入材料**：分别指定正文、SI 和其他来源文件，避免把文件角色弄混。
2. **确认读取情况和检查设置**：查看哪些文字、表格和图片已经读取，选择要用的格式模板及检查范围。
3. **运行检查**：比较数据、复算数值，列出疑点。需要读取图片表格时，先让多模态模型查看原图；需要提取文字时再使用辅助 OCR，并核对识别结果。
4. **逐项复核**：查看原文和图片，确认分子式解释、实验条件或材料归属，记录处理意见。
5. **导出和复查**：保存报告；论文修改后重新运行，检查旧问题是否解决。任务中断时，可以要求继续未完成的部分。

如果要检查图片重复，可以单独说：

> 请检查 SI 中是否有重复图片。提取图片后，由当前多模态模型逐对查看原图和必要的放大区域。程序筛查只提供辅助线索，不要只看程序已经标出的图片，也不要把 OCR 文字当作图片审核结果。把疑似重复的区域、两张图的位置和判断理由列出来，并告诉我哪些图片还没检查。

视觉复核需要当前 Harness 模型支持图片输入。图片较多时，插件会按设置分批处理，你可以要求继续；只完成一批时，报告会保留剩余的检查数量。[图片复核的详细用法](docs/VISUAL-AGENT-0.8.md)。

也可以只做单项计算：

> 按中性分子式 C2H6O 和离子 [M+H]+，复算理论 m/z。

## 怎么看检查结果

报告会给出需要复核的内容，以及原文、计算或图片依据。**先看检查范围，再看问题列表。** “没有发现问题”只适用于已经读取并完成相应检查的部分；被关闭的检查、读取失败的材料和还没处理的图片都会另外列出。

使用时，需要特别留意以下几类结果：

- **图片查重**：程序筛查仍容易漏检，视觉模型的实际检出效果也还没有完成真实材料验证。列出的相似图片需要对照用途和内容判断；没有发现重复，不能据此认定所有图片都没有问题。
- **OCR 文字**：目前使用本地英文识别模型。低清扫描、复杂合并单元格、手写、上下标和特殊符号容易读错，应回到原图确认。
- **核磁与分子式**：交换氢、对称性、信号重叠和多重峰都会影响数量比较。数量异常值得检查，但不能仅凭计数判断结构错误。
- **精确质量和实验复算**：结果依赖分子式、离子形式、反应计量关系等输入。信息不清时，报告会保留不同解释或说明缺少什么，不会自动选取最接近原文数值的解释。
- **图表与结论**：目前可核对明确引用和部分表格数值。复杂曲线、机理判断及整篇论文的论证仍需要研究者阅读和判断。

插件目前不完成原始谱图的结构确证、完整质量平衡或全文所有图表引用的核查，也不会自动把修改写回 Word。详细测试方法和结果保留在 [验证记录](docs/VALIDATION.md) 中。

## 支持的文件与数据处理

支持 DOCX、可检索文本的 PDF、TXT/Markdown、CSV、JSON、XLSX，以及 PNG、JPEG、单帧 TIFF、WebP、BMP 图像。DOCX/XLSX 文件上限为 128 MiB，其他输入为 32 MiB。

原始文件只读，项目记录和报告保存到 `dataDir`。文字判断和视觉复核使用当前 Harness 会话的模型；送入会话的文字或图片可能被发送给模型服务并进入宿主日志，具体取决于你的 Harness 配置。本地 OCR 不需要额外的 OCR 服务账号。
